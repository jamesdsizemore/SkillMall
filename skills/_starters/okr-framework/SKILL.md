# OKR Framework

Write, cascade, and grade OKRs (Objectives and Key Results) using the method John Doerr brought to Google. The framework separates aspirational direction (Objective) from measurable proof (Key Results).

## When to use

- Setting quarterly or annual goals for a team
- Cascading company OKRs into team OKRs
- Writing a Key Result that is currently described as a task ("launch feature X")
- Grading OKRs at the end of a cycle

## OKR formula

**Objective:** What we want to achieve. Inspirational, qualitative, memorable. Should feel slightly out of reach.

**Key Results:** How we know we achieved it. Measurable, time-bound, binary (either we hit the number or we do not).

Template: *"We will [Objective] as measured by [Key Results]."*

## Writing Key Results

A Key Result must be a metric that moves. "Launch X" is a task, not a Key Result. "X used by 50 engineers by March 31" is a Key Result.

Format: `[Metric] from [baseline] to [target] by [date]`

Example: "Error rate in checkout from 2.4% to under 0.5% by March 31"

## Grading

Your grading scale: [FILL-IN: grading-scale]

Google's default: 0.0–1.0, where 0.7 is success. Consistently scoring 1.0 means the target was not ambitious enough. Consistently scoring < 0.4 means it was unrealistic or deprioritized.

## Common mistakes

- Key Result is a task: "Build dashboard" → fix to "50% of users check dashboard weekly"
- Too many KRs: 3-5 per Objective maximum. More means none will be tracked.
- Sandbagging: set targets you are 70% confident of hitting, not 100%
- OKRs as a task list: OKRs are outcomes, not a sprint backlog
