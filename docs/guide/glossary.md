# Glossary

Definitions for every term used in SkillMall documentation and tooling. Terms are sorted alphabetically. Where one term is best understood alongside another, a "See also" note points you there.

---

**Agent**: An AI coding assistant — Claude Code, Cursor, Codex, Gemini CLI, GitHub Copilot, or any other tool that reads and executes skill files during a conversation. Agents discover skills at session start, match user requests against skill descriptions, and invoke the appropriate skill's instructions to guide their responses. See also: AgentSkills, Trigger phrase.

**AgentSkills**: The open standard that defines the SKILL.md file format. Because every SkillMall skill follows this standard, the same skill file works across Claude Code, Cursor, Codex, Gemini CLI, GitHub Copilot, and any other compatible agent without modification. The specification is published at agentskills.io. See also: Frontmatter, Skill.

**Artifact**: The specific output a skill produces when invoked. A skill for Blue Ocean Strategy produces an ERRC grid and a Strategy Canvas. A skill for code review produces a structured review document. A skill for incident postmortems produces a blameless postmortem report. Every well-written skill has exactly one primary artifact — the clearer the artifact, the more reliably the skill fires and the easier it is to evaluate the skill's output. See also: Artifact type, Template, Sample.

**Artifact type**: The structural category an artifact falls into. SkillMall recognizes six types: matrix (a grid comparing two axes, like an ERRC grid), canvas (a large multi-section template like a Business Model Canvas), grid (a simpler layout of cells without the analysis framing of a matrix), list (ordered or unordered items, like a review checklist), flowchart (a decision or process diagram), and analysis (a free-form structured document with headings and prose). Knowing an artifact's type helps you pick the right template. See also: Artifact, Template.

**Atomic write**: A file-writing strategy where all output files are written to a temporary location first and then moved into place in a single rename operation. If the process crashes mid-write, the destination either contains the old complete version or the new complete version — never a partially written state. The SkillMall pipeline uses atomic writes when saving research results and generated skill files to avoid corrupting an existing skill if the generation step fails.

**Budget analyzer**: A CLI tool that simulates how much of a skill's description an agent can actually read when many skills are installed. Agents have a fixed token budget for reading skill descriptions at session start; when many skills are installed, they silently truncate descriptions that exceed their share of the budget. Running `npx skill-mall budget-analyze` shows you the effective character limit per skill given your current installation and flags any skills that will be truncated. See also: Trigger phrase, Description quality.

**Category**: One of eight organizational groups that every SkillMall skill belongs to: `development`, `design`, `writing`, `research`, `productivity`, `infrastructure`, `ai`, and `business`. Categories appear in URLs (`/skills/development/code-review`), filter the catalog, and determine where a skill is stored on disk (`skills/<category>/<skill-name>/`). Each category has a display color and icon defined in `lib/categories.ts`. See also: Skill catalog, Slug.

**Chain**: A multi-skill workflow where one skill passes its output as context to the next. For example: a research skill gathers information, passes it to a writing skill that drafts a document, which passes the draft to an editing skill that tightens it. Chains are defined in a SKILL.md body by listing the sequence of skills to invoke and what to pass between them. They allow complex multi-step workflows to be expressed as composable, individually-testable units. See also: Skill, Pipeline.

**Chunk**: A segment of text, approximately 512 tokens long (around 400 words), that is the unit of storage and retrieval in a RAG knowledge base. When you attach a knowledge base to a skill, the source documents are split into chunks, each chunk is converted to an embedding (a numeric vector), and both are stored together. At query time, the chunk most similar to the user's request is retrieved and injected into the skill's context. Chunk size is a tuning parameter — smaller chunks are more precise, larger chunks provide more surrounding context. See also: Embedding, Knowledge base, RAG.

**CLI**: The `npx skill-mall` command-line tool that provides the primary interface for non-browser workflows. Key commands include `list` (enumerate installed skills), `find` (search the catalog by keyword), `deploy` (copy a skill to an agent's skills directory), `new` (scaffold a new skill from the template), `validate` (check frontmatter compliance), and `create` (run the research-first pipeline). The CLI is implemented in the `cli/src/commands/` directory and published as an npm package so users can run it without a local checkout. See also: Pipeline, Wizard.

**Collection**: A curated group of skills that can be deployed together as a single named pack. A collection might be "frontend-essentials" (code-review, PR-description, conventional-commits) or "blue-ocean-strategy-pack" (blue-ocean-strategy, competitive-analysis, strategy-canvas). Collections are defined in a YAML file and deployed with `npx skill-mall deploy-pack <collection-name>`. They are especially useful for onboarding new team members, who can deploy all of a team's standard skills in one command. See also: Deploy, Skill catalog.

**Completeness score**: One of the five quality dimensions that make up a skill's overall quality score. It measures whether the skill body has enough substance to actually guide an agent's behavior: structured headings, sufficient prose depth, concrete examples, and at minimum one named artifact output. A skill that is just a vague description of what to do scores low; one with step-by-step instructions, examples, and a clear artifact scores high. The completeness score is worth 25 of the 100 total quality points. See also: Quality score.

**Confirm research**: The second step of the CLI skill creation pipeline, run after `npx skill-mall create`. The Research Engine saves a `research-result.json` file containing the extracted tools and frameworks. Before building the final SKILL.md, the pipeline pauses and asks you to review and edit this JSON. Running `npx skill-mall confirm-research` reads the saved result, validates it, and proceeds to generate all skill files. This two-step design lets you correct extraction errors before they propagate into generated output. See also: Research Engine, Research result, Pipeline.

**Configure**: The setup step that stores an LLM provider's API key and endpoint so the pipeline can make API calls during skill generation. Running `npx skill-mall configure --provider claude-code` (or `--provider openai`, `--provider gemini`, etc.) prompts for credentials and writes them to a local config file. Without configuring a provider, the `create` command cannot run because it has no LLM to call for extraction and generation. See also: Provider, Pipeline.

**Content accuracy**: The requirement that every command, code snippet, example, and reference in a skill has been verified to work correctly. A skill that tells an agent to run a command that does not exist, or references a file that is not there, teaches the agent to produce errors. SkillMall's contribution guidelines require that any example code or command in a skill be tested before submission. Content accuracy is evaluated as part of the completeness score during PR review. See also: Completeness score, Quality score.

**Deploy**: The action of copying a skill from the SkillMall catalog (or local `skills/` directory) into an agent's skills directory so the agent can use it. Deployment is done with `npx skill-mall deploy <category>/<skill-name>` and optionally `--agent <agent-name>` or `--all-agents`. For Claude Code, deploy copies the skill directory to `~/.claude/skills/`. The skill takes effect the next time a new agent session starts. See also: CLI, Agent, Collection.

**Description quality**: One of the five quality dimensions in a skill's quality score, worth 25 of 100 points. A high-quality description starts with an action verb ("Apply", "Use", "Generate"), is under 150 characters, is specific enough that the agent invokes it only for the right requests, and puts the primary trigger phrase in the first 80 characters. Poor descriptions are vague ("helps with strategy"), too long (truncated by agent budgets), or overlap so heavily with other skills that the wrong skill fires. See also: Quality score, Trigger phrase, Budget analyzer.

**Embedding**: A numeric vector — an array of floating-point numbers — that represents a piece of text in a geometric space where similar meanings are close together. SkillMall uses embeddings to power semantic search in the catalog (so "how do I analyze competitors" finds competitive-analysis skills even without the exact words) and to implement RAG retrieval from skill knowledge bases. Embeddings are computed by an LLM embedding model and stored in the database alongside their source chunks. See also: Chunk, RAG, Knowledge base.

**ERRC grid**: A structured analytical tool from Blue Ocean Strategy (W. Chan Kim and Renee Mauborgne) that stands for Eliminate, Reduce, Raise, Create. Each row in the grid lists a competitive factor; the four columns indicate whether that factor should be eliminated entirely, reduced below industry standard, raised above industry standard, or created new (something the industry has never offered). Completing an ERRC grid forces explicit tradeoffs rather than trying to be better on every dimension. The SkillMall `blue-ocean-strategy` skill produces an ERRC grid as its primary artifact. See also: Strategy Canvas, Artifact.

**Forked skill**: An independent copy of an existing skill, created by a user who wants to customize it. The fork tracks its origin via a `forked_from` field in the frontmatter (e.g., `forked_from: business/blue-ocean-strategy`). Forks are independent files — changes to the original do not automatically propagate to forks. Fork counts are displayed on skill detail pages to show how many users found a skill worth customizing. See also: Frontmatter, Revert.

**Framework**: In the context of prompt engineering, a structured reasoning approach that an agent applies to a problem. Examples include Chain of Thought (breaking a problem into explicit reasoning steps), SWOT analysis (Strengths, Weaknesses, Opportunities, Threats), and the ERRC grid. SkillMall skills that use the research-first pipeline select the most appropriate framework from the extracted tools and build prompts around it. See also: PE framework, Prompt.

**Frontmatter**: The YAML configuration block at the top of a SKILL.md file, delimited by `---` markers. Frontmatter contains the `name` and `description` fields required by the AgentSkills specification, optional spec fields like `license` and `compatibility`, SkillMall catalog metadata (version, author, category, tags, linked-skills), and optional Claude Code extensions (when_to_use, allowed-tools). Everything between the closing `---` and the end of the file is the skill body — the instructions the agent reads and follows. See also: Slug, Linked skills, Metadata.

**Hub skill**: A skill that has many `linked-skills` connections to other skills in the catalog. Hub skills appear highlighted (larger nodes, bolder borders) in the dependency graph visualization on the catalog's graph view. A hub skill typically represents a foundational workflow or methodology that other skills build on — for example, a `debugging-session` skill might be linked from incident-postmortem, code-review, and performance-analysis skills. See also: Linked skills, Orphan skill.

**Install event**: An anonymous data point recorded in the database each time a user deploys a skill with the CLI or wizard. Each record stores the skill slug and the target agent type (e.g., `claude-code`), but no personally identifiable information. Install events power the trending page (showing which skills are being deployed most frequently) and the install-count badge on skill detail pages. See also: Deploy, Session.

**Knowledge base**: A collection of document chunks with embeddings, attached to a specific skill to support RAG retrieval. When a user invokes a skill with a knowledge base, the agent can query the knowledge base with the user's message to retrieve the most relevant chunk and inject it into context before responding. A knowledge base is created by uploading source documents to a skill and running the indexing step. See also: RAG, Chunk, Embedding.

**Linked skills**: Skills that are referenced from another skill's frontmatter via the `metadata.linked-skills` field. Linked skills are related but separate — a skill might link to prerequisite skills ("you should run competitive-analysis before this"), complementary skills ("use this with strategy-canvas"), or skills that handle adjacent use cases. The catalog visualizes linked-skills relationships as a dependency graph. See also: Hub skill, Orphan skill, Frontmatter.

**MCP**: Model Context Protocol. A protocol that allows AI agents to invoke external tools, APIs, and data sources via a standardized HTTP interface. An MCP server exposes a set of named tools with typed inputs and outputs; the agent calls them the same way it would call any built-in capability. SkillMall uses MCP for integrations that require real-time data (API calls, database queries) rather than the static instruction approach of SKILL.md files. See also: Agent.

**Metadata**: The SkillMall-specific fields nested under the `metadata` key in a skill's frontmatter. These fields — version, author, category, tags, linked-skills — are read by the catalog UI to populate search indexes, filter pages, and the dependency graph. Agents that do not understand SkillMall's extensions silently ignore the metadata block, so it does not interfere with cross-agent compatibility. See also: Frontmatter, Linked skills.

**Migration**: A SQL file in the `migrations/` directory that modifies the database schema by adding tables, columns, or indexes. Migrations are applied in numeric order by `npm run db:migrate`. Each migration is applied exactly once and recorded in a `_migrations` table so subsequent runs skip already-applied files. This pattern makes it safe to run `db:migrate` on every deploy — it is always a no-op if the database is already current. See also: WAL mode, Session.

**Orphan skill**: A skill with zero `linked-skills` connections — it neither links to other skills nor is linked from any other skill. Orphans appear with a dashed border in the catalog's dependency graph. While some skills are legitimately standalone, orphan status can also indicate that a skill was created without consideration for the broader catalog and may be missing logical connections. See also: Hub skill, Linked skills.

**PE framework**: Prompt Engineering framework. A structured reasoning approach embedded in the prompts under a skill's `resources/prompts/` directory. Each prompt file applies a specific PE framework — for example, Chain of Thought (step-by-step reasoning), Few-shot (reasoning from examples), or Role prompting (the agent adopts a specific expert persona) — to guide how the agent generates the skill's artifact. The research-first pipeline selects the most appropriate PE framework for each tool it extracts. See also: Framework, Prompt, Pipeline.

**Pipeline**: The five-stage process the CLI uses to generate a complete skill from an authoritative source. Stage 1 (research): fetch URLs and extract named tools and frameworks. Stage 2 (select): present extracted items to the user for confirmation. Stage 3 (build): generate SKILL.md, README.md, template, sample, and prompts. Stage 4 (prompt-engineer): apply the selected PE framework to each prompt. Stage 5 (write): save all generated files atomically to disk. See also: Research Engine, Confirm research, Atomic write.

**Provider**: An LLM service that the SkillMall CLI calls to power the research-first pipeline. Supported providers include OpenAI (GPT models), Anthropic (Claude models), Google (Gemini models), Groq (fast open-weight models), and Ollama (locally-run models). The provider is configured once with `npx skill-mall configure` and used for all subsequent `create` commands. Different providers have different speeds, costs, and quality tradeoffs. See also: Configure, Pipeline.

**Prompt**: An instruction file stored in a skill's `resources/prompts/` directory that applies a specific PE framework to a particular tool or methodology. For example, a `chain-of-thought.md` prompt file tells the agent to reason step by step before producing the artifact, while a `few-shot.md` prompt provides two or three examples before asking for the skill's output. Prompts allow skill authors to experiment with different reasoning approaches for the same skill without changing the main SKILL.md body. See also: PE framework, Framework.

**Quality score**: A 0-to-100 score computed for every skill in the catalog across five dimensions: description quality (25 pts), completeness (25 pts), frontmatter health (20 pts), resource richness (20 pts), and link health (10 pts). Skills must score 70 or higher to be merged into the public catalog via pull request. The score for each skill appears on its detail page along with a breakdown showing exactly which points were deducted and why. See also: Completeness score, Description quality.

**RAG**: Retrieval-Augmented Generation. A technique that gives an AI agent access to a body of knowledge too large to fit in a single context window by retrieving only the most relevant piece at query time. The agent takes the user's message, finds the knowledge-base chunk with the closest embedding, injects that chunk into context, and then generates its response with that retrieved information available. SkillMall supports attaching knowledge bases to skills so they can answer questions grounded in specific documents. See also: Knowledge base, Embedding, Chunk.

**Research Engine**: The component inside the CLI `create` command that fetches URLs, extracts their text content, and calls an LLM to identify named tools, methodologies, and frameworks worth encoding as skills. The engine returns a structured JSON list of candidates, each with a name, description, and the source URL it came from. This JSON is saved as `research-result.json` for the user to review before the build step runs. See also: Research result, Confirm research, Pipeline.

**Research result**: The JSON file (`research-result.json`) saved by the Research Engine after the first stage of the pipeline. It contains an array of extracted tools and frameworks, each with a name, a short description, the source URL, and the PE framework the engine recommends for generating the skill. The user reviews and edits this file in the confirm-research step, then the build step uses it to generate the final skill files. See also: Research Engine, Confirm research, Pipeline.

**Revert**: The action of returning a forked skill's content to match its parent skill. Reverting overwrites the fork's SKILL.md with the current version of the parent but keeps the fork's frontmatter metadata (author, version, forked_from). This is useful when the parent skill has been substantially improved and the fork's customizations are no longer needed. Revert is a destructive operation — the fork's unique content is permanently lost unless saved elsewhere. See also: Forked skill.

**Sample**: A completed example of a skill's artifact output, stored in `resources/samples/`. A sample shows what a correct, high-quality output looks like for a specific input scenario. For example, a blue-ocean-strategy skill might include a sample ERRC grid completed for a fictional ride-sharing company entering the airport taxi market. Samples help users understand what to expect from a skill and help agents calibrate the desired output format and depth. See also: Artifact, Template.

**Session**: A GitHub-authenticated user session stored as a row in the `sessions` SQLite table. When a user logs in via GitHub OAuth, the server creates a session record with a randomly generated token, the user's GitHub ID, username, and an expiry timestamp. The session token is sent to the browser as a cookie and checked on every authenticated request (writing reviews, forking skills, requesting skill improvements). See also: Install event, Migration, WAL mode.

**Skill**: A SKILL.md file containing instructions that guide an AI agent's behavior for a specific task or methodology. A skill is a structured text file, not code — it tells the agent what to do, what artifact to produce, and how to structure its output. Skills are stored in the `skills/<category>/<skill-name>/` directory alongside optional supporting files (README, templates, samples, prompts). The skill format is defined by the AgentSkills open standard. See also: AgentSkills, Frontmatter, Skill catalog.

**Skill catalog**: The complete collection of skills in the SkillMall `skills/` directory, served as a browsable web UI by the Next.js application. The catalog is parsed at build time by `lib/skills.ts` using gray-matter to read frontmatter. Each skill appears as a card showing its name, description, category, quality score, and install count. The catalog supports full-text search, category filtering, and sorting by quality score, install count, or recency. See also: Skill, Category, Quality score.

**Skill creator**: A user who has authored a skill and is identified as its owner by the `metadata.author` field in the skill's frontmatter. The skill creator's GitHub username appears on the skill detail page. Creators are the only users authorized to request LLM-generated improvement suggestions for their skills, apply suggestions, and publish new versions via pull request. See also: Frontmatter, Quality score.

**Slug**: The kebab-case identifier for a skill, formed from lowercase letters, numbers, and hyphens. The slug must match the skill's directory name exactly and is also used in the `name` frontmatter field. For example, the skill in `skills/business/blue-ocean-strategy/` has the slug `blue-ocean-strategy`. Slugs appear in URLs (`/skills/business/blue-ocean-strategy`), CLI commands (`npx skill-mall deploy business/blue-ocean-strategy`), and `linked-skills` references. See also: Frontmatter, Category.

**Starter template**: A pre-built skill in the `skills/_starters/` directory that is approximately 80 percent complete and ready for a user to customize with their team's specific details. Unlike the blank `skills/_template/` scaffold (which has placeholder text), starters have real instructions, real artifact descriptions, and real examples — they just need team-specific rules filled in. The catalog ships with starters for code review, PR writing, commit messages, debugging, incident postmortems, OKRs, user story mapping, and more. See also: Template, Skill.

**Strategy Canvas**: A Blue Ocean Strategy visualization tool that plots competitive factors on the horizontal axis and the level of investment (low to high) on the vertical axis. Each player in the market is drawn as a curve connecting its relative investment level across all factors. Plotting the incumbent industry curve alongside a proposed new offering makes the strategic difference visible at a glance. The SkillMall `blue-ocean-strategy` skill produces a Strategy Canvas as its secondary artifact alongside the ERRC grid. See also: ERRC grid, Artifact.

**Template**: A blank artifact structure stored in `resources/templates/` that users fill in when using a skill. A template is the structural skeleton of the artifact — the headings, the table rows, the labeled sections — with placeholder text but no content. For example, the ERRC grid template is an empty four-column table; the user fills in the competitive factors and marks each one. Templates give users a starting point and ensure output consistency across different uses of the same skill. See also: Artifact, Sample.

**Trigger phrase**: The key words and phrases in a skill's `description` field that an agent uses to decide when to invoke the skill. Agents compare the user's message against all installed skill descriptions and invoke the skill whose description best matches. A good trigger phrase is specific enough to avoid false positives ("Apply Blue Ocean Strategy" rather than "help with strategy"), uses the vocabulary a user would naturally type, and appears in the first 80 characters of the description where agents are least likely to truncate it. See also: Description quality, Budget analyzer.

**Version history**: The git commit log for a skill's `SKILL.md` file. Because every skill lives in a git repository, every change to a skill is recorded with a commit message, author, and timestamp. The skill detail page in the catalog includes a version history panel that shows each change, who made it, and when. Users can compare versions to understand how a skill has evolved over time. See also: Skill, Skill creator.

**WAL mode**: SQLite's Write-Ahead Logging mode. In default SQLite mode, a writer locks the entire database file, blocking all readers. In WAL mode, the database maintains a separate write-ahead log file so readers can continue reading the last committed state while a write is in progress. SkillMall enables WAL mode on all SQLite databases so that concurrent HTTP requests (readers fetching skill data) are never blocked by a write (recording an install event or creating a session). See also: Migration, Session, Atomic write.

**Wizard**: The browser-based multi-step skill creation interface at `/skills/create`. The wizard guides users through the same stages as the CLI `create` command — entering a topic and URLs, reviewing extracted tools, selecting a PE framework, previewing generated files, and publishing — using a graphical form interface instead of terminal commands. The wizard is better suited for users who are new to SkillMall or prefer a visual workflow; the CLI is better suited for scripting and automation. See also: CLI, Pipeline, PE framework.
