# Chain Format Reference

This document specifies the complete format for skill chains — both the `chain.json` configuration file and the generated `SKILL.md` frontmatter.

## chain.json

The `chain.json` file is the source of truth for a chain's structure. It is stored in `skills/chains/<slug>/chain.json` alongside the chain SKILL.md.

### Schema

```json
{
  "name": "string — human-readable name",
  "slug": "string — kebab-case identifier, matches directory name",
  "steps": [
    {
      "order": "number — execution order, 1-indexed",
      "skillSlug": "string — category/slug format",
      "passesAs": "string — context_append | context_replace | named_variable",
      "namedVariable": "string? — variable name when passesAs = named_variable",
      "usesOutput": "string? — slug of prior step whose output to use as input",
      "instructions": "string? — additional instructions for this step"
    }
  ]
}
```

### Complete example

```json
{
  "name": "Strategy Analysis Pipeline",
  "slug": "strategy-analysis-pipeline",
  "steps": [
    {
      "order": 1,
      "skillSlug": "business/blue-ocean-strategy",
      "passesAs": "named_variable",
      "namedVariable": "errc_analysis"
    },
    {
      "order": 2,
      "skillSlug": "business/competitive-analysis",
      "passesAs": "context_append",
      "usesOutput": "business/blue-ocean-strategy",
      "instructions": "Use Porter's Five Forces to contextualize the Blue Ocean findings."
    },
    {
      "order": 3,
      "skillSlug": "writing/stakeholder-communication",
      "passesAs": "context_replace",
      "instructions": "Write an executive summary of the combined analysis."
    }
  ]
}
```

### Field reference

**`name`** (required) — Human-readable display name. Used in the generated SKILL.md description and README.

**`slug`** (required) — Kebab-case identifier. Must be lowercase letters, numbers, and hyphens only. Maximum 64 characters. Must match the directory name under `skills/chains/`.

**`steps`** (required) — Array of chain steps, minimum 2. Executed in ascending `order`.

**`steps[].order`** (required) — Integer execution order starting from 1. Steps are sorted by `order` before execution, regardless of array order in the JSON.

**`steps[].skillSlug`** (required) — The skill to invoke at this step, in `category/slug` format. The skill must exist in the catalog.

**`steps[].passesAs`** (required) — How this step's output is passed to the next step:
- `context_append` — Appends this step's output to the next step's context. Default for most chains.
- `context_replace` — Replaces the context entirely with this step's output. Use when you want a clean slate.
- `named_variable` — Stores this step's output in a named variable accessible to all later steps.

**`steps[].namedVariable`** (optional) — Required when `passesAs = named_variable`. The variable name, referenced as `{{variable_name}}` in later steps.

**`steps[].usesOutput`** (optional) — Slug of a prior step whose output to use as input for this step, instead of the accumulated context.

**`steps[].instructions`** (optional) — Additional instruction text appended to this step's context when it executes.

## Chain SKILL.md frontmatter

The chain SKILL.md is generated by `buildChainDirectory()` and follows the AgentSkills spec with chain-specific metadata extensions.

### Schema

```yaml
---
name: "<slug>"
description: "Run a coordinated <name> analysis using <N> skills in sequence."
license: MIT
metadata:
  version: "1.0.0"
  author: "<author>"
  category: chains
  tags: "<comma-separated tags>"
  chain: true
  chain_steps:
    - skill: <category/slug>
      passes_as: <passesAs value>
      # optional fields:
      uses_output: <category/slug>
      instructions: "<instruction text>"
      named_variable: <variable_name>
---

# <Chain Name>

<step list as numbered text>
```

### Complete example

```yaml
---
name: strategy-analysis-pipeline
description: "Run a coordinated Strategy Analysis Pipeline analysis using 3 skills in sequence."
license: MIT
metadata:
  version: "1.0.0"
  author: "jamesdsizemore"
  category: chains
  tags: "strategy, analysis, pipeline"
  chain: true
  chain_steps:
    - skill: business/blue-ocean-strategy
      passes_as: named_variable
      named_variable: errc_analysis
    - skill: business/competitive-analysis
      passes_as: context_append
      uses_output: business/blue-ocean-strategy
      instructions: "Use Porter's Five Forces to contextualize the Blue Ocean findings."
    - skill: writing/stakeholder-communication
      passes_as: context_replace
      instructions: "Write an executive summary of the combined analysis."
---

# Strategy Analysis Pipeline

1. business/blue-ocean-strategy
2. business/competitive-analysis (uses: business/blue-ocean-strategy)
3. writing/stakeholder-communication
```

### Validation rules

The generated chain SKILL.md must pass `validateSkillDirectory()`:

- `name`: required, kebab-case, ≤ 64 characters
- `description`: required, ≤ 1024 characters (warn above 150)
- `metadata.chain`: must be `true`
- `metadata.chain_steps`: must be present with at least 2 entries
- `README.md` must be present in the same directory

## API reference

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/chains` | GET | List all chains in `skills/chains/` |
| `/api/chains/<slug>` | GET | Get chain.json for one chain |
| `/api/create-chain` | POST | Validate and write a new chain |

### POST /api/create-chain body

```json
{
  "chain": {
    "name": "My Pipeline",
    "slug": "my-pipeline",
    "steps": [...]
  },
  "metadata": {
    "slug": "my-pipeline",
    "category": "chains",
    "tags": ["analysis"],
    "targetAgents": ["claude-code"],
    "author": "your-github-username"
  }
}
```

Returns 201 on success with `{ slug, path, steps }`. Returns 422 if validation fails with `{ errors }`.
