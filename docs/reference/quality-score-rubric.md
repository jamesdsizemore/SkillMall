# Skill Quality Score Rubric

Every skill in the catalog receives a quality score from 0 to 100, computed by `lib/quality-score.ts`. The score appears on skill cards and the detail page with per-dimension breakdown and actionable feedback.

## Scoring Dimensions

Total: 100 points across 5 dimensions.

---

### Dimension 1: Description Quality (25 points max)

| Criterion | Points |
|---|---|
| First sentence uses an imperative verb (Apply, Run, Analyze, Use, Execute, Generate, Create, Build, Perform, Conduct, Evaluate, Assess, Produce, Identify, Extract, Implement, Write, Review, Plan) | 7 |
| Description is 150 characters or fewer | 6 |
| Trigger phrase (skill name words) appears in the first 80 characters | 7 |
| Description is specific — names the domain, tool, or workflow (not only generic verbs like "help", "assist", "provide") | 5 |

---

### Dimension 2: Completeness (25 points max)

| Criterion | Points |
|---|---|
| `README.md` is present | 5 |
| At least one file in `resources/templates/` | 7 |
| At least one file in `resources/samples/` | 7 |
| At least one file in `resources/prompts/` | 6 |

---

### Dimension 3: Frontmatter Health (20 points max)

| Criterion | Points |
|---|---|
| All required fields present: name, description, metadata.category, metadata.tags, metadata.version, metadata.author | 8 |
| `metadata.category` value is in the valid taxonomy (development, design, writing, research, productivity, infrastructure, ai, business) | 4 |
| `metadata.tags` count is between 2 and 6 | 4 |
| Directory name matches the `name` field exactly | 4 |

---

### Dimension 4: Resource Richness (20 points max)

Scored on total count of files in `resources/templates/`, `resources/samples/`, `resources/prompts/`, and `scripts/`:

| Total resource file count | Points |
|---|---|
| 1–3 | 5 |
| 4–7 | 10 |
| 8–14 | 15 |
| 15 or more | 20 |

---

### Dimension 5: Link Health (10 points max)

- All skills referenced in `metadata.linked-skills` exist in the catalog: 10 points
- Proportional deduction per broken link: `−(10 / total_linked_skills)` per missing skill, rounded to nearest integer

---

## Feedback Message Format

Every deduction generates a specific, actionable message:

```
"Description starts with 'This skill helps' — rewrite to start with an imperative verb like 'Apply' or 'Run' (-7)"
"No sample outputs in resources/samples/ — add at least one completed artifact example (-7)"
"Description is 187 characters (exceeds 150-character limit) — shorten it (-6)"
"Linked skill 'okr-framework' not found in catalog — remove the link or install the skill (-5)"
"Missing required fields: version, author (-8)"
"Tag count is 1 — keep between 2 and 6 (-4)"
```

## Score Interpretation

| Score | Interpretation |
|---|---|
| 90–100 | Production-ready, well-documented skill |
| 70–89 | Good skill, minor improvements possible |
| 50–69 | Usable but missing documentation or resources |
| Below 50 | Needs significant work before publishing |
| Below 40 | Template or placeholder — do not publish |

Skills generated by the pipeline with full URL research typically score 75–90. Skills scaffolded from the `_template` score below 40 until populated.
