# Publishing Skills to skills.sh

SkillMall skills can be published to the [skills.sh](https://skills.sh) public registry, making them installable by anyone via `npx skills add <slug>`.

## Pre-Publish Requirements

All four checks must pass before the publish flow opens:

| Check | Requirement |
|---|---|
| Quality score | >= 70 out of 100 |
| Description length | <= 1024 characters |
| Name matches directory | `name` field in SKILL.md must match the directory name exactly |
| License field | `metadata.license` must be present (e.g., "MIT") |

Check your skill's quality score on its detail page at `localhost:3000/skills/<category>/<slug>` before attempting to publish.

## Running the Publish Command

```bash
npx skill-mall publish <category/slug> --registry skills.sh
```

**Example:**
```bash
npx skill-mall publish business/blue-ocean-strategy --registry skills.sh
```

### What happens:

1. **Pre-publish validation runs** — all 4 checks evaluated. If any fail, the command exits with specific error messages. No OAuth flow opens until all checks pass.

2. **OAuth flow opens** — a browser window opens to authenticate with skills.sh. Complete the OAuth flow in the browser.

3. **Skill data is posted** — the skill metadata and content is sent to the skills.sh API.

4. **SKILL.md frontmatter is updated** — two fields are added to the SKILL.md file:

```yaml
metadata:
  skills_sh_id: "abc123"
  skills_sh_url: "https://skills.sh/skills/abc123"
```

After these fields are written, the skill detail page shows a "Published on skills.sh" badge.

## Pre-Publish Validation Failure Examples

**Quality score too low:**
```
✗ [quality_score] Quality score 58/100 is below the minimum 70 required for publishing
```
Check the quality score breakdown on the detail page. Common causes: missing README, no templates, no samples, description not starting with an imperative verb.

**Name mismatch:**
```
✗ [name_matches_dir] Skill name "my-skill" does not match directory name "my-skill-v2"
```
Either rename the directory or update the `name` field in SKILL.md to match.

**Missing license:**
```
✗ [license_present] metadata.license field is required for publishing (e.g., "MIT")
```
Add `license: MIT` to the top-level frontmatter of SKILL.md.

## After Publishing

Anyone can install your published skill:

```bash
npx skills add your-github-username/blue-ocean-strategy
```

The published skill remains the version at time of publish. To update an already-published skill, run `publish` again — the `skills_sh_id` field is overwritten with the new version's ID.

## Note on OAuth Status

The skills.sh OAuth flow implementation requires the skills.sh OAuth endpoint documentation. The pre-publish validation and frontmatter update are fully implemented. If the OAuth flow returns an error about the implementation being incomplete, the validation has already confirmed your skill is publish-ready — resume once the OAuth integration is finalized.

## Improving Your Quality Score Before Publishing

If your quality score is below 70, here are the most impactful improvements:

**Description quality (25 pts max):** Start the description with an imperative verb ("Apply", "Run", "Analyze"). Keep it under 150 characters. Put the skill name or domain in the first 80 characters.

**Completeness (25 pts max):** Add a README.md, at least one template in `resources/templates/`, at least one sample in `resources/samples/`, and at least one prompt in `resources/prompts/`. Each is worth 5-7 points.

**Frontmatter health (20 pts max):** Ensure `version`, `author`, `category`, and `tags` are all present. Keep tags between 2 and 6. Directory name must match the `name` field.

**Resource richness (20 pts max):** 15+ files across templates, samples, prompts, and scripts earns maximum 20 points. Skills generated by the full pipeline typically score 75-90.

## Version Management

Follow semver when bumping `metadata.version` in SKILL.md:
- Patch (1.0.0 → 1.0.1): typo fixes, clarity improvements only
- Minor (1.0.0 → 1.1.0): new templates, prompts, or tool coverage
- Major (1.0.0 → 2.0.0): changed output format or breaking changes

Re-publishing updates the `skills_sh_id` in your frontmatter to the new version.
